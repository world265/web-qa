# Тестовая стратегия

## Цель

Проверить, что основные игровые действия сохраняют прогресс, корректно изменяют экономику и дают игроку понятную обратную связь.

## Подход

### Risk-based testing

Глубина проверки определяется возможным ущербом:

- потеря прогресса и платежей проверяется наиболее глубоко;
- merge и награды покрываются позитивными, негативными и прерываемыми сценариями;
- UI/UX проверяется после подтверждения функциональной корректности.

### Black-box testing

Проверки выполняются через наблюдаемое поведение интерфейса. Серверные причины можно предполагать только по сетевым запросам и журналам браузера, если они доступны.

### Exploratory testing

Используется для игровых механик, где полная спецификация отсутствует:

- переполненная карта;
- быстрые повторные действия;
- переход между устройствами;
- прерывание рекламы;
- состояние после обновления игры.

## Уровни проверки

### Smoke

- игра запускается;
- прогресс загружается;
- предмет можно переместить и объединить;
- задание обновляется;
- награда начисляется;
- баланс ресурсов отображается;
- основные окна открываются.

### Functional

- правила merge;
- уведомления;
- события;
- рабочие;
- реклама;
- покупки;
- аккаунт и синхронизация.

### Regression

Проводится после изменений в:

- merge logic;
- экономике;
- событиях;
- системе сохранения;
- авторизации;
- рекламе;
- платёжной интеграции;
- адаптивности интерфейса.

### Compatibility

Минимальная матрица:

- Windows 11: Chrome, Яндекс Браузер, Edge;
- типовые разрешения 1366×768 и 1920×1080;
- масштаб браузера 80%, 100%, 125%;
- узкое окно с боковой рекламной панелью.

Матрица предлагается для будущего выполнения; исходное задание подтверждает только Windows 11.

## Техники тест-дизайна

- классы эквивалентности для количества предметов и значений ресурсов;
- граничные значения для merge, балансов и полей профиля;
- таблицы решений для рекламы и покупки;
- state transition для награды: unavailable → available → claimed;
- pairwise для браузера, разрешения, масштаба и наличия боковой панели;
- error guessing для repeated click, refresh, disconnect и crash.

## Данные и доказательства

Для каждого инцидента фиксируются:

- версия игры;
- ОС и браузер;
- разрешение и масштаб;
- Player ID;
- время;
- состояние аккаунта;
- баланс до и после;
- шаги;
- скриншот или видео;
- network/console evidence, если доступно.

## Entry criteria

- доступна тестируемая сборка;
- известна версия;
- подготовлен тестовый аккаунт;
- зафиксирован начальный прогресс и баланс;
- доступна возможность восстановить тестовые данные.

## Exit criteria

- P0 smoke пройден;
- нет открытых blocker/critical дефектов, влияющих на прогресс, покупки и аккаунт;
- High-дефекты имеют согласованное решение;
- известные ограничения отражены в release report;
- результаты и evidence сохранены.
