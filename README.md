# Browser Game QA Case

**Проект:**  Тестирование кросс-браузерной игры
**Продукт:** Браузерная merge-игра «Соединённое Королевство»  

## О проекте

Тестирование и исследование браузерной игры не только с позиции проверки интерфейса, но и с позиции игрового прогресса, пользовательского опыта и поддержки игроков.

Что проделано:

- поиск дефектов и проблем удобства использования;
- предложения по улучшению игровых механик;
- подготовку ответов на отзывы игроков;
- формирование уточняющих вопросов для расследования инцидентов.


## Что демонстрирует проект

- исследовательское тестирование браузерной игры;
- анализ UI/UX-проблем;
- понимание merge-механик и игрового прогресса;
- оценку рисков ресурсов, наград, покупок и синхронизации прогресса;
- оформление дефектов с доказательствами;
- разделение дефекта, UX-проблемы и предложения по улучшению;
- подготовку ответов пользователям;
- сбор диагностических данных для расследования инцидентов;
- формирование регрессионного покрытия на основе наблюдаемых рисков.

## Подтверждённый scope исходного задания

В исходных материалах непосредственно рассмотрены:

- индикатор доступного действия у персонажа Lord;
- панель предложений и событий;
- изменение имени игрока;
- диагональное объединение предметов;
- merge предметов группами по 3, 5 и 10;
- использование Liquid Rainbow;
- временные рабочие Genie;
- синхронизация прогресса через аккаунт Яндекса;
- покупки и случайное списание gems;
- рекламные награды;
- награды событий;
- потеря прогресса;
- сбои после обновления;
- проблемы авторизации.

## Ключевые выводы

1. Главный риск игры — не отдельный визуальный дефект, а блокировка или потеря прогресса игрока.
2. Уведомления должны означать реальное доступное действие, иначе игрок перестаёт им доверять.
3. События, награды и реклама должны проверяться как единая цепочка: условие → просмотр/выполнение → подтверждение → начисление → сохранение.
4. Покупки и премиальная валюта требуют подтверждения, идемпотентности и возможности расследования по Player ID и времени операции.
5. Поддержка является частью качества продукта: хороший ответ не обещает неподтверждённое решение, а собирает данные для воспроизведения и расследования.

## Ограничения

Проект основан на тестовом задании и black-box наблюдениях. Нет доступа к требованиям, исходному коду, базе данных, логам, административной панели и внутренней аналитике. Поэтому предложенный регрессионный чек-лист является моделью покрытия, а не отчётом о фактически выполненных проверках.
