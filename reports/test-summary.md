# Test Summary Report

## Объект

Браузерная merge-игра «Соединённое Королевство».

## Основание

Отчёт составлен по результатам тестового задания, включавшего UI/UX-анализ, предложения по улучшению, ответы игрокам и диагностические опросники.

## Окружение

- Windows 11.
- Браузер, версия, разрешение и масштаб не зафиксированы.

## Фактически зафиксированные результаты

### Проблемы

1. **BUG-001:** индикатор у Lord отображается без полезного доступного действия.
2. **BUG-002:** панель событий и предложений обрезана справа или не предоставляет понятный доступ ко всем элементам.

### Предложения по улучшению

1. Свободное изменение имени игрока.
2. Поддержка диагонального merge или более понятная обратная связь о допустимых позициях.

### Поддержка

Подготовлены ответы на двенадцать типов сообщений игроков, включая:

- недовольство обновлением;
- непонятную механику;
- дефицит ресурса;
- назначение предметов;
- рекламу;
- монетизацию;
- случайную трату gems;
- перенос прогресса между устройствами.

### Расследование инцидентов

Подготовлены диагностические вопросы для:

- неначисленной покупки;
- потери прогресса;
- crash после обновления;
- неначисленной награды события;
- неначисленной рекламной награды;
- проблемы авторизации.

## Оценка качества исходного тестового задания

### Сильные стороны

- проблемы описаны с точки зрения влияния на игрока;
- expected и actual разделены;
- предложения по улучшению выделены отдельно;
- ответы поддержки сохраняют вежливый тон;
- для критических инцидентов собираются Player ID, время и evidence.

### Недостатки, исправленные в case study

- не были указаны браузер, версия, разрешение и масштаб;
- отсутствовали формализованные шаги воспроизведения;
- severity не отделялась от priority;
- некоторые ответы могли опираться на непроверенную механику;
- отсутствовала явная граница между выполненными проверками и предлагаемым покрытием.

## Решение

По двум UI/UX-проблемам недостаточно данных для окончательного решения о выпуске всей игры. Они сами по себе не блокируют релиз, но BUG-002 может получить более высокий приоритет, если скрытые события становятся недоступны.

Выпуск не должен оцениваться без отдельного smoke по:

- загрузке и сохранению прогресса;
- merge;
- наградам;
- покупкам;
- авторизации и синхронизации.

## Рекомендация

1. Уточнить окружение и повторно проверить два зафиксированных дефекта.
2. Подтвердить продуктовые требования к уведомлениям и переполнению панели.
3. Не классифицировать свободное имя и диагональный merge как bugs без требований.
4. Выполнить P0/P1 регрессию перед использованием проекта как полноценного release case study.
